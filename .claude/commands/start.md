# /start — открыть сессию разработки KARMAN

Парная команда к [`/close_session`](close_session.md). Подхватывает контекст без пересказа.

## Шаг 1. СНАЧАЛА синхронизация, ПОТОМ чтение состояния (pool #032)

Жёсткий порядок: handoff читается **только после** pull — иначе работаешь по устаревшему
состоянию, а свежий handoff с другой машины приедет позже и спутает картину.

Синхронизируется **только этот репозиторий**. Чужие репо (`../brain_matrica`, соседи) —
read-only, никаких `fetch`/`pull`/`checkout` там (мандат владельца 08-04, канон — `AGENTS.md`).

```bash
git fetch
git status --short --branch          # дерево чистое?
git pull --ff-only                   # ТОЛЬКО при чистом дереве; конфликт/не-ff — разобраться руками
bash scripts/git_sync_check.sh --warn
git log --oneline -5
```

Грязное дерево или расхождение веток — **сначала** разобраться (это может быть оборванная
сессия: восстановление — из Git/PR/handoff, не по памяти чата), и только потом продолжать.

## Шаг 2. Прочитать состояние (после sync!)

1. `docs/SESSION_HANDOFF.md` — нитка. При устаревшем `Updated:` (старше пары недель) — не
   доверять слепо, сверить с `git log`.
2. **Почта brain — два канала, читать оба** (мандат владельца 08-04). Локальную копию
   `brain_matrica` **не синхронизировать**: там может лежать чужая рабочая ветка с ещё не
   запушенной почтой, и `pull`/`checkout` эту работу рвут.

   ```bash
   # канал A — локальный диск, как есть
   ls ../brain_matrica/mailboxes/KARMAN/from-brain/*.md
   # канал B — GitHub main, без clone/fetch/pull
   gh api "repos/Valstan/brain_matrica/contents/mailboxes/KARMAN/from-brain?ref=main" \
     --jq '.[] | select(.type=="file") | .name'
   ```

   Набор писем = **объединение** каналов; отсутствующее локально письмо читать через
   `gh api ... /contents/<путь> --jq .content | base64 -d`.

   **Свежесть считается по каждому письму отдельно**, свежесть одного файла (или репозитория)
   на другие не переносится. Письмо есть в обоих каналах и версии различаются:

   - незакоммиченная локальная версия — **свежее** (`git -C ../brain_matrica status --short -- <путь>`);
   - иначе сравнить дату последнего коммита **именно этого пути** (обе стороны в UTC, иначе
     строки со смещением не сравниваются):
     `TZ=UTC git -C ../brain_matrica log -1 --date=iso-strict-local --format=%cd -- <путь>` против
     `gh api "repos/Valstan/brain_matrica/commits?path=<путь>&sha=main&per_page=1" --jq '.[0].commit.committer.date'`;
   - порядок не определяется (даты равны, истории разошлись) — **прочитать обе версии, явно
     отметить конфликт в отчёте, ничего не перезаписывать**.
3. `docs/PENDING_FOLLOWUPS.md` — **всплыть** протухшее (pool #033 + амендмент brain 07-28).
   Возраст считается **из даты `last-touch`**, а не из слова-статуса: слово рядом с датой
   деградирует молча (дата протухла — слово нет), поэтому статусного поля в файле нет.
   Всплывает:
   - обычный пункт с `last-touch` **старше 30 дней** или `snoozed ≥ 3`;
   - `parked` — **только когда выполнилось его условие `until:`** (или условие перестало
     быть проверяемым — тогда пункт не парк, а протухшее);
   - `recurring` — когда пропущен ритм `every:` относительно `last-run:`.

   Ре-триаж — четырьмя исходами: возобновить / переформулировать под текущий код /
   выкинуть с причиной / **запарковать** (только с проверяемым условием расконсервации;
   без условия `parked` = `stale` под другим именем). Не всплывшее — не трогать.
   Секция «Чужой ход» стареет не по этим правилам: наша работа там закончена.

## Шаг 3. Подсветить нитку

Только то, что нужно для решения «продолжаем нитку?», без пересказа файлов:
- **Status / нитка** из handoff + **следующий шаг**.
- **Почта:** есть ли необработанные письма от brain (директивы — в очередь задач).
- **Отложенное:** всплывшие stale-пункты и итог ре-триажа.
- **Синхронизация:** предупреждения `git_sync_check.sh` — разобраться **до** новой работы.
- Если на другой машине осталась feature-ветка с открытым PR — напомнить
  `git fetch && git checkout <branch>`.

> Завершать сессию — через `/close_session` (закоммитит+запушит всё, обновит handoff, проверит гейт).
