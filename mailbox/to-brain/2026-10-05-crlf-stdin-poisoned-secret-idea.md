# Находка для пула: пайп Windows → ssh дописывает CRLF

**Класс:** значение секрета, переданное через stdin (`Get-Content -Raw | ssh`),
приезжает с хвостовым `\r` — PowerShell дописывает CRLF в stdin нативного
процесса. Дальше два поражения одним ударом:

1. Значение ложится в env/БД с `\r` внутри (сверка eyeball чистая — `\r` не виден).
2. Запросы с таким Bearer режет **сам llhttp пустым 400 без заголовков**
(`Connection: close`, тело 0) — а проверки без секрета (401) и с чужим (401)
при этом зелёные, и ловушка «auth работает» держит до конца.

**Сигнатура для опознания:** 401/401 везде верные + пустой 400 только с боевым
токеном. Сверка — `od -c` значения, не eyeball. Лечение — `tr -d '\r\n'` на
принимающей стороне до записи.

**Смежное:** `Get-Content -Raw` без `-Encoding utf8` в PS 5.1 портит байты уже
при чтении (кириллица в ушедшем файле — двойной ширины кракозябры, md5 не
сходится); показ тут ни при чём. И `curl -v` с Bearer светит секрет в лог —
после такого ключ ротировать, не «заметить».

Цена у нас: час отладки живого relay + одна ротация. Дарю класс целиком.
