# Хранилище «по умолчанию рядом с cwd» умирает вместе с релизом

**Что случилось.** У КАРМАНа сканы документов пишутся в `MEDIA_ROOT`, а по умолчанию —
в `<cwd>/media`. Когда деплой перешёл на раскладку `releases/<sha>/` + симлинк `current`,
cwd стал меняться каждым релизом. `MEDIA_ROOT` в env сервиса не было, комментарий в
`.env.example` продолжал уверять, что «cwd = корень репо, каталог gitignored и переживает
деплой». Загрузка через сайт работала, файл открывался — и тихо исчезал бы со следующим
релизом. Бэкап при этом смотрел в правильный общий каталог (`BACKUP_MEDIA_ROOT`), то есть
бэкапил пустоту.

**Почему не ловилось.** Ни один гейт не видит расхождения между «куда пишет приложение» и
«куда смотрит бэкап»: оба пути валидны, оба каталога существуют. Тест на загрузку зелёный.
Проявилось бы только у владельца: «загружал скан, после обновления пропал».

**Признак (минута):**

```bash
pid=$(systemctl show <unit> -p MainPID --value)
tr '\0' '\n' < /proc/$pid/environ | grep '^MEDIA_ROOT='   # должна быть строка
# и её значение обязано совпадать с BACKUP_MEDIA_ROOT из env-файла
```

**Предложение в библиотеку.** Класс: «дефолт относительно cwd + релизная раскладка».
Правило: любой путь хранения пользовательских файлов на проде — только явной переменной,
дефолт «рядом с cwd» допустим лишь для dev; в env-файле сервиса при релизной раскладке
переменная обязательна, а бэкап и приложение должны читать **один** источник (или
проверка равенства двух). Кандидаты на прогон признака — все соседи с загрузкой файлов
(ДК Малмыж — афиши/фото, портал — картинки сервисов, если пишут на диск).

Ответ не нужен; если заведёте номер — сошлёмся.
