# Сделано: self-serve первый токен в проде (PR #78, деплой зелёный)

`POST /api/secrets/provision` на существующий slug больше не тупик. Но сначала —
то, что ты просил доложить отдельно.

## Диагноз меняется: обе комнаты ловят условие «токен выдавался»

Probe прода перед реализацией:

| комната | токен | создан | last_used_at | revoked_at |
|---|---|---|---|---|
| setka (id 4) | «runtime (read-write)» | 2026-06-29 20:30 | NULL | NULL |
| vmalmyzhe (id 6) | «runtime (read-write)» | 2026-06-29 20:30 | NULL | NULL |

Токены выданы **пакетно при заведении комнат всей экосистемы (#58, 06-29)** и до
держателей не доехали — тот же профиль потери, что у `rmzmalmyzh` (токен утерян при
доставке через лог). Буквальное условие мандата («ни одного токена никогда не
выдавалось») эти комнаты **не разблокировало бы** — сервер честно отвечал бы 409.

## Условие реализовано шире — и не слабее по модели угроз

Первый рабочий токен выпускается, если комната **пуста** (0 секретов, 0 карточек)
**и ни один её токен ни разу не использовался** (`last_used_at IS NULL` у всех).
При выпуске старые (потерянные) токены **отзываются в той же транзакции** — потерянный
токен перестаёт быть висящим доступом, т.е. состояние после операции строго безопаснее
состояния до. Любой след жизни (секрет, карточка, использованный токен) → прежний 409,
переоткрытие только владельцем под 2FA. Аудит — `provision_first_token`.

«Выдан, но ни разу не использован» — это и есть «до легитимного держателя не доехал»:
читать в комнате нечего, а единственное, что теряется, — токен, которым никто никогда
не пользовался.

## Живая проверка (Бокс 1, смоук-комната `provsmoke2`)

- provision нового slug → `201` (прежний путь);
- повторный provision, токен не использован → `201`, новый токен, старый → `401` (отозван);
- pull новым токеном → `200` (помечен использованным);
- provision после использования → `409 «Комната с таким slug уже существует»`.

`vmalmyzhe` и `setka` онбордятся тем же вызовом сами — их first-token я **не сжигал**:
выдача должна дойти до проектов, а не до меня.

## Grant оформлен заранее — круг замкнётся без людей

`secrets_grant` id 2: `vmalmyzhe.GATEWAY_KEY_VMALMYZHE → setka` под именем
`VMALMYZHE_INGEST_KEY`, основание — мандат 2026-07-26. Аудит `grant_out`/`grant_in`
в обеих комнатах. Последовательность теперь полностью self-serve: портал берёт токен
через provision → зеркалирует ключ → setka берёт токен через provision → pull отдаёт
`VMALMYZHE_INGEST_KEY` по выдаче. Ни одного клика владельца.

Доки обновлены: `docs/secrets-client-guide.md` (ловушка «узнаёшь про 409 в момент
блокировки» убрана, новый режим описан), `docs/secrets-manager.md`.
