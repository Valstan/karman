## Что сделано (PR #135, прод `6522e3e`)

Строже, чем «четыре строки как у соседа», потому что четыре строки закрывают вход, а не
поверхность:

| Проверка | Ответ | Зачем |
|---|---|---|
| `X-Relay-Secret` ≠ `RELAY_SECRET` | 403 | вход |
| `RELAY_SECRET` не задан у воркера | **503** | fail-closed: воркер без переменной — закрыт, а не «как раньше» |
| метод HTTP не GET/POST | 405 | |
| путь не `/bot<token>/<метод>` или метод вне allowlist (`getUpdates`, `sendMessage`, `answerCallbackQuery`, `editMessageReplyMarkup`, `getMe`) | 404 | «любой метод через чужой аккаунт» больше недоступен даже с секретом |
| заголовки звонящего | не проксируются, наружу только `content-type` | сам секрет и `cf-*` до Telegram не доезжают |

Исходник — `scripts/cloudflare/karman-tg.js`, контракт — `karman-tg.test.ts` (8 тестов, в
гейте). Секрет — в env-файле бокса как `TELEGRAM_RELAY_SECRET`, заголовок шлют три
клиента (`lib/telegram/client.ts`, `scripts/reminders-worker.mjs`, `scripts/health_watch.sh`).
Порядок без обрыва: секрет в env + деплой кода (старый воркер лишний заголовок игнорирует)
→ переменная у воркера → новый код воркера. Напоминания не прерывались.

**Приёмка подсадным с бокса (#114), 11.09 ~20:20 UTC:**

```
no-header getMe        403
wrong-header getMe     403
header getMe           200
header deleteWebhook   404
header DELETE getMe    405
header root /          404
```

После смены кода воркер напоминаний за три минуты не написал ни строки (он пишет
только сбои) — `getUpdates` через закрытое реле идёт.

Про «секрет через вашу же комнату»: секрет лежит в env бокса рядом с
`TELEGRAM_BOT_TOKEN`, комнату `karman` не трогал — это тот же класс секрета, что токен
бота, и второй дом ему не нужен. Если у вас на это другой взгляд — скажите.
