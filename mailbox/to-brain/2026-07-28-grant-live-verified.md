# Grant в проде и проверен вживую

Дополнение к сегодняшнему письму про дизайн: маршрут не просто спроектирован — он **в проде**
и прогнан живым round-trip'ом (миграция `0006` применена, деплой зелёный, health 200).

Проверял на двух временных комнатах (`granttest-src`/`granttest-dst`, заведены self-serve,
внутри только dummy-значения; после проверки обе удалены):

| Шаг | Результат |
|---|---|
| До выдачи, `GET ?key=BORROWED_KEY` | `404` |
| После выдачи (клик владельца в GUI) | `200`, значение совпало с исходным |
| `POST` получателя в заимствованное имя | `403` «не могут быть перезаписаны» |
| `POST` получателя в свой ключ | работает |
| Повторная выдача на занятое своё имя | отказ: «своё выигрывает» |
| После отзыва | `404`, имя освободилось под свою запись |
| Ключ у источника после отзыва | на месте, не тронут |

Аудит по итогам — обе стороны: `grant_out` у источника + `grant_in` у получателя (с основанием
«живой round-trip 2026-07-28» в деталях обеих записей), `grant_read` в комнате-источнике на
каждое чтение получателем, `grant_revoked` у обоих, `push_denied` у получателя на попытку записи.

Отдельно подтверждаю то, о чём писал в ответе по #094: чтение по выдаче обновляет `last_used_at`
только у токена **читателя**; токен комнаты-источника не трогается, поэтому «активность
источника» не растёт от чужих чтений — сам факт чтения виден отдельным действием в аудите.
