# Надстроенный PR после squash-мержа базового: в diff попадает чужая работа

## Как выглядит

PR B надстроен на PR A (ветка B содержит коммиты A — так удобно, когда A ещё не смержен).
PR A смержили **squash**'ом (у нас это правило репозитория, и squash-merge не даёт
переписывать историю опубликованных веток). После этого «Files changed» у PR B
начинает показывать изменения **обоих** PR.

## Почему

База слияния (merge base) — общий предок до A, потому что squash-коммит A в `main`
имеет **другой хеш**, чем коммиты A в ветке B. GitHub считает diff от merge base, а не
по дереву, поэтому правки A (теперь уже в `main`) снова оказываются в диффе B. Ревьюер
видит в «своём» PR чужую работу, и объём диффа удваивается.

## Что не работает

`git rebase` + force-push: в репозитории с защищённым `main` форс-пуш запрещён, и
переписывать историю уже опубликованной ветки нельзя.

## Что работает

**Merge `main` в ветку**: `git merge origin/main --no-edit`. Merge-коммит делает
squash-коммит A предком ветки B, база слияния сдвигается на него — и в diff PR B
остаётся только работа B. Код не меняется, история не переписывается, force-push не
нужен.

## Побочный эффект, о котором стоит знать заранее

Squash-мерж такой ветки соберёт в тело коммита сообщения **всех** коммитов ветки
(включая A). Если subject задавать вручную (`gh pr merge --subject`), то и хвоста
«(#N)», который GitHub добавляет сам, не будет. Код не затронут, но `git log` на
`main` станет шумнее. Мы это оставили и записали в handoff: переписать историю
`main` нельзя.

## Проверенный порядок

1. смержить базовый PR (A) — дождаться зелёного деплоя;
2. **влить `main` в ветку надстроенного PR (B)** и запушить;
3. дождаться зелёного CI у B;
4. смержить B.

Проверено в KARMAN 04.11: PR #251 → `ea29d92`, PR #252 → `68adcce`. До шага 2 дифф #252
показывал и правки #251, после — только перестройку экрана.

## Мысль

Надстроенность PR — это не только про порядок мержа, но и про то, **что ревьюер
увидит**. Стоит проверять дифф после мержа базового PR: если в нём вдруг оказалась
чужая работа, это не «шум», а признак, что база слияния уехала.
