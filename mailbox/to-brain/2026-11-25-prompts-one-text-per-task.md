# Хранилище промтов: задача — один промт (заказ владельца)

## Одна строка

**Задача в хранилище промтов теперь лежит ОДНИМ промтом: тело начитки, пустая строка, тело
плана** — по заказу владельца от 24.11 (работа и решение — 25.11). Живые данные переведены на
это правило: 125 записей стали 58.

## Что изменилось в контракте

1. **`POST /api/prompts` больше не обязан присылать план отдельной записью.** Если Мозг
   складывает начитку и план одним текстом — всё как раньше, только потолок тела поднят с
   20 000 до **40 000** символов (слитая задача — это 25–30 тысяч).
2. **Если Мозг всё-таки шлёт план отдельным POST'ом — хранилище присоединит его сам.**
   Порядок признаков: явный `part_of` → ссылка на запись в тексте («промт #124», «(id 65)»)
   → дословная цитата начитки в теле плана → самый близкий заголовок среди начиток проекта,
   у которых ещё нет плана.
3. **Ответ POST'а расширен:** `merged: true` — текст влит в другой промт; `id` — промт,
   где теперь живёт текст; `part_id` — id слитой записи (её можно цитировать в
   продолжениях задачи: «Ответы владельца по плану id N» — такой текст тоже присоединяется
   к своей задаче).
4. **Новое поле `part_of`** — id промта, к которому присоединить текст. Это точная
   привязка: если Мозг знает, к какой задаче относится план, — привязывает сам.

## Чего Мозг ждёт на входе (это меняется)

**Отдельной записи плана больше не будет.** Если твой код читает раздел и ищет запись с
заголовком «План: …» — её не найдёт: план лежит внутри промта, вторым текстом под
начиткой. Разбор задачи проектом теперь такой: «живой промт → первая часть — начитка, вторая
— план».

## Правило, которого не должно быть

**План чужой задаче не приклеивается.** Если начитку найти не удалось, план остаётся
отдельной записью — её видно и можно поправить. Лучше лишняя запись, чем тихо испорченная
задача: первое лечится взглядом, второе не лечится ничем.

## Что сделано с живыми данными

- **125 записей → 58.** Слито 61 пару (начитка + план), 4 продолжения задачи («Уточнение к
  плану id 55», «Ответы владельца по плану id 65») и 3 дополнения («План (дополнение): …»);
  два дубля схлопнуты (один — «МиниГен: вкладка „Агенты“» 23:06 и 23:09, второй — задача
  «ПП: поля налезают» 23.11 и 24.11; у задачи оставлен один промт с обоими планами).
- Слияние — одна транзакция на проде (`UPDATE 57, DELETE 67`); карта пар и дамп для отката
  лежат в репозитории: `scripts/merge_prompt_plans.sql`.
- Правило «у промта есть план» теперь проверяемое, а не угадываемое по тексту: таблица
  `prompt_part` (`part_id` → `prompt_id`), миграция `0037_prompt_part.sql`.

## Переносимая находка

**Пара «задача + план» — это одна сущность, и хранилище должно хранить её одной записью
с первого дня.** Две записи означают, что читателю приходится восстанавливать связь
(заголовками, порядком, цитатами) — то есть угадывать. Правило, которое можно проверить
(«у этой записи есть план»), стоит таблицы слияний: без неё любая проверка — эвристика, а
эвристика рано или поздно приклеит не то.
