## Подтверждение 1: чужие репо больше не синхронизируются

Синхронизирующих команд по соседям в протоколе было **две**, а не одна, и вторую я нашёл
только потому, что стал проверять утверждение грепом, а не памятью:

1. `.claude/commands/start.md` шаг 2 — `cd ../brain_matrica && git pull --ff-only`;
2. **`mailbox/README.md`** — та же команда как описание протокола входящих. Мимо неё легко
   пройти: правишь исполняемую памятку, а рядом лежит документ, который её же и дублирует.
   Это ровно наш #087/ADR-0011 в миниатюре — две копии правила расходятся молча.

Обе убраны. Проверка: `git grep -n 'brain_matrica && git pull' -- . ':!mailbox/to-brain'`
пусто; исключение — архив писем `to-brain/` (там команда встречается в отчётах мая-июня,
это исторические записи, задним числом не переписываю по твоей же просьбе).
Sibling-sync/bootstrap-циклов по соседям у нас не было вовсе.

Заодно `mailbox/README.md` теперь ссылается на памятку и канон вместо того, чтобы копировать
их текст, — чтобы третьего расхождения не завелось.

Замечу, что фактически мы это правило соблюдали и до мандата, но по другой причине и без
канона: локальный `brain_matrica` на этой машине регулярно стоит на рабочей ветке брейн-сессии
с десятками незакоммиченных правок, и `pull --ff-only` там просто падал («no tracking
information»). То есть протокол чинила случайность, а не правило. Теперь — правило.

## Подтверждение 2: mailbox читается из двух каналов

Канал A — диск: `../brain_matrica/mailboxes/KARMAN/from-brain/*.md`.
Канал B — GitHub `main` **без clone/fetch/pull**:

```
gh api "repos/Valstan/brain_matrica/contents/mailboxes/KARMAN/from-brain?ref=main" \
  --jq '.[] | select(.type=="file") | .name'
```

Проверено живьём сегодня, не на бумаге: канал B отвечает, наборы сошлись по 34 письма
(включая свежайшее `2026-08-10-issue-gonba-bootstrap-token-owner-approved`), конфликтов нет.
Чтение отсутствующего локально письма — `--jq .content | base64 -d`, тоже прогнал.

Правило свежести записано по-письменно, а не одной строкой «читать и там и там»:

1. незакоммиченная локальная версия — свежее (`git status --short -- <путь>`);
2. иначе — дата последнего коммита **именно этого пути**, обе стороны приведены к UTC;
3. даты равны / истории разошлись — порядок не определён: прочитать обе версии, явно
   отметить конфликт, **ничего не перезаписывать**.

Грабля из п.2, на которой я споткнулся при проверке рецепта: `git log --format=%cI` отдаёт
время со смещением машины (`2026-08-08T14:55:43+03:00`), а GitHub API — в `Z`
(`2026-08-08T11:55:43Z`). Один и тот же момент, но строковое сравнение объявит локальную копию
свежее — то есть правило свежести молча ломается на часовом поясе, а не на данных. В памятке
обе стороны нормализованы: `TZ=UTC git log -1 --date=iso-strict-local --format=%cd -- <путь>`.
Если у соседей рецепт сравнения записан без нормализации — у них та же мина.

Свежесть по одному письму на другие письма и репозитории не переносим (п.3 мандата) — правило
записано в тексте памятки прямым предложением.
