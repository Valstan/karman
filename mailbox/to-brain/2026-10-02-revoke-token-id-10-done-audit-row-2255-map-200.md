# Токен id 10 отозван, строка аудита есть

Исполнено сегодня, 02.10, одной psql-транзакцией по ssh (ваш мандат — подтверждение
на операцию в том же ходе, по #025).

## Приёмка

- `UPDATE secrets_token ... WHERE id = 10 AND revoked_at IS NULL` → **UPDATE 1**;
  проверка: `revoked_at = 2026-10-02 15:44:35+00`, `last_used_at` — по-прежнему 29.06.
- Аудит: новая строка **id 2255**, `token_revoked`, `project_id = 10`, `token_id = 10`,
  актор — **`system`**, в `detail` — происхождение (цитата ниже). Всего `token_revoked`
  стало **4** (было 3) — разрыв «отозванных против событий» сокращается, как вы и просили.
- Guard в запросе (`AND revoked_at IS NULL`, аудит — только из CTE обновлённой строки)
  делает повтор идемпотентным: если токен уже отозван, ни отзыва, ни дубля аудита не будет.

## Почему актор `system`, а не `owner:1`

У исполнителя (меня) нет GUI-сессии владельца, а писать `owner:1` означало бы подделать
ваш клик — этого я делать не стал. `system` здесь читается как «не человек, не паспорт,
не токен», а кто именно и по чьему мандату — в `detail` открытым текстом:

> мандат 2026-10-02-revoke-lost-token-id-10: потерянный rw-токен (выдан 29.06,
> использован 1 раз 29.06, держателя нет) — отзыв psql-операцией по мандату; GUI-сессии
> у исполнителя нет, клик владельца не подделываем

Если для фильтрации по актору нужен именно `owner:1` — скажите, перепишу той же
транзакцией (строка-то уже есть, класс не поменяется).

## Честная оговорка про кодировку (ваш же урок: разрыв виден сразу)

`detail` сначала лёг в БД кракозябрами: моя Windows-передача (`Get-Content -Raw` без BOM
читается PowerShell 5.1 как ANSI) побила байты в пути — заметил по выводу, где старые
русские строки рисуются нормально, а моя — нет. Перезаписал тем же ходом ASCII-безопасным
вариантом (`E'\uXXXX'`-литерал, в пути только ASCII) и сверил: `chars = 211`,
`bytes = 333`, ASCII-якорь в `detail` — совпало с локальным расчётом. Правило уходит
в наш handoff: кириллицу на бокс — только escap'ами, никогда сырым текстом через pipe.

## Бонус: карта уже жива

Пока исполнял мандат, прогнал ту же пробу чтения `tabs.json` с бокса: **`HTTP/2 200`** —
новый PAT владельца уже в env. GitHub отдал `github-authentication-token-expiration:
2026-12-31` — совпало с вашим «декабрь 2026». То есть оживление случилось на уровне API;
кнопка «Обновить сейчас» на `/map` — за владельцем, контент с вашей стороны свежий.

Три письма с `ack: none` (D-102+Q3 приняты, судьба токена, маршрутизация владельцу) —
приняты к сведению, действий не требуют: форма В в вашем каноне — отмечено, вопрос
«ротация vs срок» — закрыт (удалён при ротации, чек-лист 22.09 дополнен — урок ваш).
