# След, выключатель и страж сделаны; про удаление digest — это уборка по отвязке

## Одна строка

**Закрыли все три пункта** (PR #378, код в `main` после мержа): след на **каждый** проход
синхронизации, выключатель `REMINDER_SYNC_ENABLED` рядом с задачей и страж-тест, который
роняет сборку, если след исчезнет; **про удаление digest — это не чистка по сроку и не
остаток прежней логики, а уборка по отвязке Telegram-чата у живого фича «Сводка KARMAN»** —
значит, след обязателен, и он теперь есть.

## 1. След на каждый проход

`lib/services/reminder-sync.ts` теперь возвращает результат прохода и **всегда** пишет
строку в журнал приложения — даже когда изменений нет:

```
[reminders/sync] синхронизация доменных напоминаний: удалено 0, создано 0, починено расписаний 0
```

Раньше было наоборот: роут отдавал JSON и в консоль не писал, воркер логировал только
ошибку — оператор не видел ни старта задачи, ни её хода, а удаление строк происходило.

Дополнительно:

- **строка о старте задачи**: воркер при старте пишет `диспетчер напоминаний запущен, тик
  раз в 25 с`;
- результат прохода едет и в **ответе диспетчера** (`sync` в JSON) — то есть след виден
  не только в журнале приложения, но и в ответе, который читает воркер.

## 2. Выключатель рядом с задачей

`REMINDER_SYNC_ENABLED` (по умолчанию **включено** — поведение не меняется молча).
Значения `0`, `false`, `off`, `no` снимают задачу, не трогая диспетчер напоминаний.
Когда задача снята, след всё равно пишется: `синхронизация доменных напоминаний выключена
(REMINDER_SYNC_ENABLED)` — иначе «задача выключена» и «задача молчала» выглядели бы
одинаково.

Переменная описана в `docs/telegram-reminders.md` и в `.env.example`.

## 3. Страж (тест на след)

`lib/services/reminder-sync.test.ts` — 5 кейсов на pglite:

1. след пишется на проход **без изменений** (удалено 0, создано 0) — если строка исчезнет,
   тест падает;
2. выключатель снимает задачу: в базе нет ни одной строки дайджеста, а след говорит
   «выключена»;
3. значения флага: по умолчанию включено, `0`/`false` выключают, `1` не выключает;
4. поведение не сломано: дайджест привязанному создаётся, дайджест отвязавшегося удаляется;
5. страж: след есть и содержит счётчики.

## 4. Ответ на ваш вопрос про удаление digest

> удаление строк `digest` у отвязавшихся пользователей — это чистка по сроку (тогда след
> обязателен) или остаток прежней логики (тогда по решению владельца задача удаляется из
> кода)?

**Ни то, ни другое: это уборка по отвязке.** Условие удаления — не срок, а отсутствие у
пользователя активного Telegram-чата (`telegram_link.is_active` / `chat_id IS NOT NULL`).
Фича «Сводка KARMAN» живая: у каждого привязанного пользователя есть ежедневный дайджест,
а расписание чинится, если `next_fire` пуст. Отвязался — дайджест больше некуда слать, и
мы его убираем, чтобы он не копился.

Отсюда: **след обязателен** (сделали), а задача из кода **не удаляется** — это не остаток,
а жизнь фича. Если владелец решит, что ежедневная сводка ему больше не нужна, тогда дайджест
и его уборка снимаются вместе — скажите, и снимем.
