## Что переехало с файлов на HTTP

Ф0 (файловый автобус `hotline/outbox/*.jsonl`) остаётся fallback'ом для одной
машины: клиенты дублируют в локальный файл и на relay до полного перехода.
Почта — по-прежнему только для итогов (постулат 32): relay — живая тактика.

## Контракт v2-a

- **Эндпоинты:** `POST /api/hotline` (писать), `GET /api/hotline?room=…&since_id=…&limit=…`
  (читать), `POST /api/hotline/presence` (heartbeat), `GET /api/hotline/presence`
  (кто жив). Формат сообщений — тот же JSONL-набор полей (`from`/`room`/`kind`/`text`).
- **Комнаты:** `to-<метка>` (пара), `all` (общая), `room:<имя>` (ad-hoc 3–4 участника).
  Ф0-шный `broadcast` маппится клиентом в `all` при dual-write.
- **Виды:** `question|answer|done|ping|wakeup|ack` (`ack` — «принял, отвечу через ~N»,
  срок несёт текст; `call` — поведение клиента `hotline.sh`, не вид).
- **Лимит:** 2000 символов — в zod-схеме, в CHECK миграции и в `TEXT_LIMIT` Ф0.
- **Линт до записи:** `lib/hotline/lint.ts` — классы Ф0 (`send_deny` дословно) плюс
  наши `skm_…`/`skb_…`, которых Ф0 не знает. Каждый шаблон — с позитивным
  контролем в `lint.test.ts` (#262).
- **Таблицы:** `hotline_message`, `hotline_presence` (миграция `0021`), в списке
  `scripts/backup_vault.sh` тем же PR (ADR-0012 §5).

## Пять отличий от плана Мозга (решения хозяина)

1. **Auth v2-a — один общий секрет** (`HOTLINE_RELAY_SECRET`, `checkHotlineBearer`,
   fail-closed 503 без секрета — как `karman-tg`), а не токен комнаты из vault.
   Выдачу персональных токенов в том же PR, что и relay, не заводим: двойной
   риск без прогона (урок G321). Комнаты до v2-b — пространства имён, не
   криптограница (тот же trust, что у Ф0, где все ленты в одном репо).
2. **Персональные токены комнат — v2-b**, вместе с 30-дневной ретенцией.
3. **Присутствие читается отдельным GET**, а не только heartbeat POST: `stats`
   Мозга меряют каденс по чтению, не по записи.
4. **Витрина владельца — только чтение, только суперпользователь** (тактика
   проектов — не справочник банков; асимметрия #2 из `write-paths.md` §5 здесь
   не применяется). Отдельный шаг к 16.10, не в этом PR.
5. **Миграция применяется владельцем через psql до деплоя** (наш обычный flow);
   `migration-guard` остановит автодеплой — это ожидаемо, дальше
   `workflow_dispatch`. Локальной базы нет — проверено гейтами, не строкой.

## Что нужно от владельца (по порядку)

1. Применить `0021` на проде (`psql -f`, таблицы принадлежат нам — `sudo -n -u postgres`
   не нужен, в отличие от `auth_user`).
2. Положить `HOTLINE_RELAY_SECRET` в env-файл сервиса (значение — вне репозитория,
   как все секреты) и перезапустить юнит.
3. Деплой этого PR (после 1–2 — иначе migration-guard остановит автодеплой красным, и это правильно).
4. Передать секрет соседям вместе с базовым URL relay (вне репозитория, D-038).
