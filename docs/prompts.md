# Промты: библиотека по проектам (заказ владельца 2026-11-06)

> Заказ владельца: «сделай в кармане вкладку промты, разделы по проектам, у
> каждого промта кнопка копировать и кнопка в архив; архив — отдельно, с датой
> создания, и его можно почистить; промты надиктовываются в чат, Мозг их
> раскладывает по проектам». Разбор решения — в ADR репозитория Мозга.

## Что это

Вкладка **«Промты»** на странице `/map` (рядом с вкладками Мозга: Планы,
Серверы, Ферма, Дела владельца, Телефон). Внутри — разделы по проектам;
внутри раздела — промты, свежие сверху.

У каждого промта:

- **«Копировать»** — кладёт текст в буфер обмена (дальше он уходит в нейронку);
- **«В архив»** — убирает промт из живого списка, **но не удаляет**: строка
  остаётся в базе с датой архивации;
- **дата создания** — когда промт создан (и когда отправлен в архив).

Архив — отдельный вид того же списка (`/map?tab=prompts&view=archive`): там
промт можно **вернуть** в живые или **удалить** насовсем, а сверху — кнопка
**«Очистить архив»** (и вариант «очистить старше даты»). Чистка архива — ручное
действие, потому что архив имеет свойство разрастаться.

## Почему не в репозитории Мозга

Остальные вкладки карты — это файлы `docs/map/*.md`, которые Мозг правит в
своём репозитории, а КАРМАН читает по GitHub API (токен только на чтение).
Промты в этот ряд не помещаются: у них есть кнопки, которые меняют состояние
(архив, удаление), а писать в репозиторий Мозга из приложения нечем. Поэтому
источник правды — **таблица `prompt`** в БД КАРМАНА, а Мозг кладёт туда
промты через машинный API.

## Канал записи (Мозг → КАРМАН)

`POST /api/prompts` с `Authorization: Bearer $PROMPTS_INGEST_SECRET`:

```json
{ "project": "Карман", "title": "ТЗ для кассы", "body": "Напиши ТЗ для кассы…" }
```

- `project` — название раздела (из реестра Мозга `projects/INDEX.md`), до 64 символов;
- `title` — необязателен; пусто — берётся первая строка промта;
- `body` — сам промт, до 20 000 символов.

Ответ: `201` и `{ id, project, title, created_at }`. Ошибки: `400` (плохое
тело), `401` (чужой токен), `429` (частые запросы), `503` (секрет не задан —
канал выключен).

`GET /api/prompts?project=…&archived=1` — прочитать библиотеку (Мозг
подтягивает промты проекта, когда работает над ним).

**Секрет — отдельный**, а не `HOTLINE_RELAY_SECRET`: промт из библиотеки
копируется в буфер и уходит в нейронку, то есть прямо в рабочий контекст
владельца и его разработчиков. Секрет relay'а знают все бэкенды-участники
комнаты Телефона, и выдавать им право писать в библиотеку промтов незачем.

Значение живёт в env-файле сервиса на боксе (`/etc/karman/karman.env`) и в
хранилище Мозга на машине владельца (`~/.brain_matrica/secrets.env`) — **вне
репозиториев** (D-038). Без переменной эндпоинт отвечает 503, а сама
страница работает: библиотеку можно наполнять и вручную из интерфейса.

## Кто что может

| Действие | Кто |
|---|---|
| Посмотреть библиотеку | **свои** промты (владелец строки) |
| Добавить, архивировать, вернуть, удалить, очистить архив | свои промты (каждый вошедний управляет своей библиотекой) |
| Записать промт через API | машинный канал Мозга (Bearer) — от имени живого аккаунта владельца |

Библиотека **личная**: «информация у каждого аккаунта видна только ему; разделы
и кнопки видны всем; исключение — Круг» (заказ владельца 2026-11-06). Фильтр —
`ownership()` из `lib/auth/rbac.ts`, **без исключения для суперпользователя**:
владелец администрирует аккаунты, но чужие промты не видит — иначе согласие в
Круге было бы декоративным.

Машинный канал (`POST /api/prompts`) пишет от имени **живого аккаунта
владельца** — активного суперпользователя с наименьшим id: сессии у канала нет,
а промт без хозяина не пишется (нет такого аккаунта → 503).

## Схема

Миграция `0025_prompts.sql` (создание) + `0026_prompt_user_id.sql` (личность;
ручная, как все):

| Колонка | Смысл |
|---|---|
| `id` | идентификатор |
| `user_id` | **владелец строки**; NOT NULL, FK на `auth_user` |
| `project` | раздел (название проекта) |
| `title` | короткое имя для списка; пусто — первая строка промта |
| `body` | текст промта — ровно то, что уходит в буфер |
| `source` | `manual` (человек) или `brain` (Мозг) |
| `created_at` | когда создан |
| `archived_at` | когда отправлен в архив; `NULL` — живой |

Нормализация текста при записи — детерминированная (`lib/prompts/normalize.ts`):
CRLF → LF, висячие пробелы, лишние пустые строки. Смысл текста не трогается:
этим занимался Мозг до отправки.

Таблица в бэкапе (`scripts/backup_vault.sh`, `-t prompt`) — по прямому заказу
владельца: промты сохраняются «на будущее, мало ли где пригодится — для
обучения или для истории».

## Что нужно от владельца (по порядку)

1. Применить `0025_prompts.sql` на проде (`psql -f`; таблица наша, `sudo -n -u
   postgres` не нужен — в отличие от `auth_user`).
2. Положить `PROMPTS_INGEST_SECRET` в env-файл сервиса на боксе и перезапустить
   юнит.
3. Задать то же значение в `~/.brain_matrica/secrets.env` на машине Мозга
   (`PROMPTS_INGEST_SECRET=…`, `PROMPTS_URL=…`) — вне репозитория.
4. Задеплоить этот PR (до 1–2 migration-guard остановит автодеплой красным, и
   это правильно; дальше — `workflow_dispatch`).
