## Failed approaches (этой нитки)

- **`psql -c "select …"` через ssh** — psql разбирает аргументы по пробелам («extra
  command-line argument … ignored», «Peer authentication failed for user "name"»). Работает:
  файл + `scp` на бокс + `psql -f` (кириллица едет без искажений).
- **BOM в первой строке SQL-файла** (`Get-Content -Raw` по файлу с BOM) — psql падает с
  «syntax error at or near "﻿select"». Лечится: первая строка файла — пустая dummy-команда
  или файл едет на бокс как есть (тогда BOM не появляется).
- **Кириллица в SQL-литералах на проде** — `title ilike 'План%'` не сработало: литерал,
  проехавший через pipe, искажается, а `chr()` даёт мусор. Проверки по тексту — только
  побайтно (`left(title,1) = E'\320\237'`) или вообще по id.
- **`\b` в JS-регексе не считает кириллицу буквой слова** — `/^План\b/` не проходило для
  «План: …». Правильно: `/^План(?![\p{L}])/u`.
- **Грубый стем «отрезать два символа»** не сводит «планшете» и «планшет» (разная длина) —
  обрезка обрезала по-разному. Работает обрезка до пяти букв.
- **Доступ агенту к `/var/log/nginx/access.log` заблокирован** runtime-гейтом, у сервиса
  HTTP-доступ-лога нет (журнал пишет только сторож напоминаний) — коды ответов смотреть
  живой пробой `curl` к роуту.
- **Удаление через ssh одним комбинированным вызовом** (`sudo rm` + `ls | grep`) — гейт
  блокирует («bypass mode does not auto-run delete-like commands»). Работает: удаление и
  проверка РАЗНЫМИ вызовами, а файл, принадлежащий postgres, — отдельным `sudo -n rm -f`
  (иначе «Operation not permitted»).
- **С 09:00 25.11 гейт блокирует ЛЮБОЙ `rm` по ssh** («HOST_CAPABILITY_UNAVAILABLE: хост не
  может спросить разрешение») — даже одиночный файл, который в 08:42 удалился штатно. Это
  ограничение рантайма, а не запрет хозяина: обходить через синонимы (`unlink`) не стал,
  файлы снёс владелец (пункт 7 «Следующий шаг»).
- **Порт 3000 на боксе — это GONBA, а не КАРМАН.** Смоук по `127.0.0.1:3000` отдаёт 404 на
  `/minimax` и `/api/prompts/section` — это чужое приложение, и 404 легко принять за регресс.
  КАРМАН слушает **3002**; `readlink /proc/<pid>/cwd` показывает и порт, и задеплоенный коммит
  (`~/karman/releases/<sha>`). Правильный смоук на 3002: health 200, `/` и `/minimax` 307,
  раздел без токена 403, POST без секрета 401.
- **Часы на машине владельца и боксе — МСК**, а метка времени в контексте сессии может быть
  другой: сверять время по `ssh karman date -u`, а не по памяти.

## Не забыть (low-priority)

- Учёт остатка очков панель не отдаёт (`points` клетки — номинал), поэтому сколько очков
  потребитель уже СЖЁГ — узнать нельзя. Сколько мы СОБРАЛИ и сколько ОТДАЛИ — леджер знает
  точно (`claimed_at` / `handed_at`).
- Забор в момент выдачи — это **один запрос к вендору на кандидата**. При большом потоке
  (десятки выдач в сутки) это нормально; при тысячах — считать.
- Отметка о выдаче в леджере пишется **по `claim_id`**, а не по дате: вендорские сутки и наши
  московские — разные календари (окно 00:00–03:00 МСК).
- Панель и лечащий МиниГен лежат вне git: после правки их надо перезапустить (супервизор 8098,
  `/stop` → `/start`), иначе в памяти старый код.
- Порядок сортировки по названию зависит от локали машины (кириллица и латиница меняются
  местами между Windows и Linux) — в тестах на это опираться нельзя (поймал гейт CI на PR
  #399).
