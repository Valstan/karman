## Failed approaches (этой нитки)

- **Бокс недоступен с машины агента:** ни `~/.ssh`, ни алиаса `karman`, ни ключа —
  `ssh karman` даёт «Could not resolve hostname». Причина по сути правильная: ключ
  деплоя живёт ТОЛЬКО в секретах Actions, и на машине владельца он настроен руками.
  Значит «прогнать что-то на проде из сессии» = либо воркфлоу с тем же ключом, либо
  руками владельца. Для бэкапа сделан `.github/workflows/run-backup.yml` (команда
  зашита, произвольную строку на прод выполнить нельзя).
- **Squash-merge дописывает номер PR к теме:** GitHub берёт тему PR и добавляет
  `(#NNN)`. Если номер был в теме уже — получилось «(#239) (#239)» в коммите на
  `main` (`72ae12d`). История `main` не переписывается, поэтому лечение — только на
  будущее: **в теме PR номер не указывать**, его добавит GitHub.
- **`PGDATABASE="$DATABASE_URL"` НЕ разворачивается libpq:** подключение ушло на
  unix-сокет с ролью текущего пользователя («role … does not exist»), потому что URI из
  этой переменной не разворачивается. Рабочий способ — **`.pgpass`** (файл 600) плюс URI
  без пароля в argv. Проверено на боевой машине: с `.pgpass` `select 1` отвечает и
  настоящий `pg_dump` отдаёт дамп, без — «no password supplied».
- **PowerShell-пайп на бокс бьёт скрипт:** первая строка приходит с BOM (теряется), а
  последняя — с CR (падает «command not found»), плюс `cat` внутри скрипта, читаемого
  из stdin, **съедает остаток самого скрипта**. Обходы: SQL передавать отдельным вызовом
  (`ssh karman "cat > файл"`), скрипты подавать **байтами** через `ProcessStartInfo`
  (`.StandardInput.BaseStream.Write`), на боксе снимать BOM через `sed -i '1s/^\xef\xbb\xbf//'`.
- **Локальный прокси `127.0.0.1:10809` мёртв** — `git fetch/push` и `gh` падали с
  «Failed to connect». Работает прямое соединение: `git -c http.proxy= -c https.proxy= …`
  и сброшенные `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` для `gh`. Тот же прокси ронял и
  `npm run build` (next/font тянет Inter из Google Fonts) — сборка идёт с прозрачными
  прокси.
- **Правило-детектор срабатывает на самом себе:** новые правила gitleaks поймали
  образцы выгрузки в `lib/security/dump-detect.ts` и его тесте — то есть на первом же
  CI. Обход — исключение **по пути и ровно для своих двух правил** (как у
  `lib/validation/secret.test.ts` и `hotline.lint.test.ts`), а не ослабление регекса.
- **PR в конфликте не запускает CI:** после мержа #234 PR #235 стал `CONFLICTING`, и
  push в ветку нового коммита **не создал ни одного run**. Вылечено: rebase на `main`
  с разрешением конфликта в handoff и `push --force-with-lease`.
- **`git checkout -- <файл>` после проверки откатывает и нужные правки:** при проверке
  гейта на подложенной координате строка была добавлена в `lib/api/client-ip.ts`, и
  откат вернул файл к состоянию **до** вычистки (замена примера адреса на адрес из
  RFC 5737) — гейт снова покраснел. Проверка отката — внимательнее, какой именно файл
  трогаем.
- **`gh api … --jq '… + " " + …'` на Windows-PowerShell:** кавычки внутри jq съедаются,
  и gh получает лишний аргумент («accepts 1 arg(s), received 2»). Рабочий обход: jq без
  кавычек внутри (`--jq .object.sha`) либо разбор ответа в PowerShell.
- **Гейт `scripts/git_sync_check.sh` падал на CRLF:** рабочее дерево на Windows отдало
  `.sh` с CRLF, а `bash` здесь — без `core.autocrlf` → «478 изменённых файлов» (ложь).
