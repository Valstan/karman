## Failed approaches (этой нитки)

- **Искать причину «чужого сертификата» в DNS — тупик.** У зоны `вмалмыже.рф` wildcard:
  резолвится любое имя, включая выдуманное. «DNS настроен» не доказывает ничего; доказывает
  только `subject` сертификата в живом ответе.
- **Верить `nginx -t`** — конфиг с неверным `server_name` синтаксически безупречен.
- **Чинить вход владельца со стороны домена** — домен был ни при чём: в базе было два
  суперюзера, вводились почта от одного и пароль от другого.
- **Плейсхолдеры в systemd-юните без смены процедуры установки** — юнит копируется на прод
  через `cp` из собственной шапки, и плейсхолдеры в нём означали бы мёртвый сервис. Поэтому
  не «заменить значения», а перевести в шаблон + рендер.
- **Требовать `BACKUP_MEDIA_ROOT` до того, как он задан на проде** — сломало бы ночной бэкап
  молча. Порядок обязателен: сначала переменная в env бокса, потом обязательность в скрипте.
- **lookahead в правиле gitleaks** — движок RE2, lookahead нет вовсе; конфиг не
  компилировался, и гейт падал паникой на каждом прогоне, то есть не мог позеленеть никогда.
- **Исключение allowlist, написанное про строку, но сверяемое со значением** — правило для
  postgres-URI имело исключение, которое не могло совпасть никогда (`regexTarget = "line"`).
- **Оставить ветку мутационной приёмки «до конца дня»** — с `fetch-depth: 0` сканер видит
  все ветки, и подсадной секрет краснил посторонний PR.

## Прод-инфра (для следующей сессии)

- **ssh:** алиасы `karman` и `GONBA`. Соединение иногда рвётся по таймауту — повтор той же
  команды проходит. Деструктив на прод-БД — только с подтверждением владельца в том же ходе
  (#025). Read-only probe — без вопросов.
- **Грабля psql по ssh:** `$DATABASE_URL` в env юзера НЕТ, переменные — в env-файле сервиса.
  Рабочая форма: `ssh karman 'set -a; . <env-файл>; psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f -'`,
  SQL слать целиком через stdin. Колонки аудита: `at`, `action`, `detail`, `actor`.
- **Внешние URL проверять С БОКСА** — с рабочей машины исходящий HTTPS идёт через прокси и
  таймаутит; `gh` при этом работает, но логи Actions иногда не тянутся (TLS timeout) —
  тогда состояние шага смотреть через `gh api …/jobs`.
- **Heredoc и бэкслеши:** при передаче многострочного текста через оболочку обратные слэши
  схлопываются, ломая `printf '%s\n'` и переносы строк в коде. Писать без escape-последовательностей
  (`echo`, `String.fromCharCode(10)`) либо файлом.
- **`main` защищён:** required check `gates`, PR обязателен, `enforce_admins`. Мержить после
  зелёного CI: `gh pr merge <N> --squash --delete-branch` (без `--admin`).
- **Миграции:** `deploy-prod.yml` блокирует авто-деплой на коммите с новой миграцией →
  применить psql'ом, затем `gh workflow run deploy-prod.yml --ref main`.
- **Деплой теперь возит `scripts/`** на бокс вместе с артефактом — ручная копия каталога
  больше не расходится (класс поймали на `backup_vault.sh` от 11 июля).
- **systemd-юниты — шаблоны**, не готовые файлы: рендер через `scripts/render_unit.sh`
  (значения из repo-vars + env-файла). `cp` из репозитория положил бы сервис.
- **Бэкап vault:** cron 03:30, `scripts/backup_vault.sh`; список таблиц догоняет схему
  вручную. Учебное восстановление прогонял владелец 15.08 — звено расшифровки проверено.
