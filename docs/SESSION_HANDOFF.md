## Failed approaches (этой нитки)

- **`createRemoteJWKSet` из jose как кеш ключей — не подошёл.** Его кеш живёт в памяти
  процесса (не переживает рестарт) и падает вместе с недоступным issuer'ом. Форма
  stale-if-error требует снимка в БД — сделан `passport_jwks_cache`.
- **Сессия как новый вид предъявителя — отвергнута в пользу «обычный токен комнаты со
  сроком».** Так клиент волны 1 меняется в одной строке, весь контур `/api/secrets`
  (grant'ы, аудит, allowlist) работает без правок, а каскад отзыва достаётся даром.
- **Выключить `PROVISION_KEY_ENABLED` по умолчанию (как в §7 ADR) — не стали.** Паспорт
  ещё не прошёл пилот; гашение живого канала до пилота — поломка под видом ужесточения.
  Волна 5 теперь стоит одной переменной без выкатки кода.
- **`revokeIdentity`/`countLiveSessions` в сервисе — написаны и удалены до коммита.**
  Вызывающих у них не было бы до GUI-вехи, а это ровно тот born-unused класс, что
  рецидивировал трижды. Отзыв личности пока — SQL-runbook + проверка на каждом чтении.

## Прод-инфра (для следующей сессии)

- **ssh на Бокс 1 есть:** алиасы `karman` и `GONBA` (ключ `id_ed25519_gonba_deploy`).
  Деструктив на прод-БД — только с подтверждением владельца в том же ходе (#025).
- **Грабля psql по ssh:** `$DATABASE_URL` в env юзера НЕТ — переменные в
  `/etc/karman/karman.env`. Рабочая форма:
  `ssh karman 'set -a; . /etc/karman/karman.env; psql "$DATABASE_URL" -c "…"'`.
  Строки с `$` в двойных кавычках раскрывает удалённый шелл — литералы слать как `$$…$$`
  или SQL целиком через stdin (`psql -v ON_ERROR_STOP=1 -f -` — так шла миграция `0007`:
  `git show HEAD:lib/db/migrations/0007_*.sql | ssh karman '… psql … -f -'`).
  Колонки аудита: `at`, `action`, `detail`, `actor` (не `created_at`/`details`).
- **Секрет через ssh/gh — не через argv** (`curl --config -`, `gh secret set` через stdin).
- **systemd-юнит деплой НЕ синхронизирует** — только `systemctl restart`. Правка юнита
  применяется руками: `git show HEAD:scripts/karman.service | ssh karman 'sudo tee …'` +
  `daemon-reload` + `restart`. Файл в репо сверен с боевым 08-10.
- **Внешние URL проверять С БОКСА, а не с PC40:** с рабочей машины исходящий HTTPS идёт
  через прокси и таймаутит. `gh` при этом с PC40 работает нормально.
- **`main` защищён технически:** required check `gates`, PR обязателен, `enforce_admins: true`.
  Мержить после зелёного CI: `gh pr merge <N> --squash --delete-branch` (без `--admin`).
- **Миграции:** `deploy-prod.yml` блокирует авто-деплой на коммите с новой миграцией →
  применить psql'ом с машины, затем `gh workflow run deploy-prod.yml --ref main`. Guard
  видит только последний коммит (тех-долг выше).
- **Vault:** штатный вход — паспорт CI (`POST /api/secrets/session`, `docs/passport-server.md`);
  `POST /api/secrets/provision` под `VAULT_PROVISION_KEY` — break-glass, гасится
  `PROVISION_KEY_ENABLED=false`. Grant между комнатами — GUI владельца под 2FA, машинного
  grant не будет. Бэкап vault: cron 03:30, `scripts/backup_vault.sh` (список таблиц
  догоняет схему вручную — см. отложенное).
