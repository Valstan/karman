## Failed approaches (этой нитки)

- **Гейт `npm audit` в CI был красный 13 дней, и никто не заметил:** последний зелёный ран
  `main` — 19.10, после него вышли advisory (next ≤16.4.0 — critical RCE, zod <4.6.6 — high),
  а гейт `npm audit --omit=dev --audit-level=high` стоит в конце пайплайна: typecheck/lint/test/
  build проходят, красным выглядит только он, и PR не мертжит. Вылечено точечным бампом
  (next ^16.4.3, zod ^4.6.7, PR #232) — **не** `npm audit fix` по дереву (класс «audit fix
  ломает несвязанное дерево» уже был 06.10). Урок: зелёная история `main` ≠ зелёный гейт
  сегодня; перед планированием работы глянуть гейты на свежем PR, иначе нитка не сдвинется.
- **`gh api --jq 'select(.type=="file")'` на Windows-PowerShell — падает:** кавычки съедаются,
  jq получает `file` без кавычек («function not defined: file/0»). Рабочий обход: `--jq '.[].name'`
  и фильтрация в PowerShell.
- **Локальный гейт `scripts/git_sync_check.sh` падал на CRLF:** рабочее дерево на Windows
  отдало `.sh` с CRLF, а `bash` здесь — WSL-git 2.25 без `core.autocrlf` → «478 изменённых
  файлов» (ложь; на боксе и в CI всё LF). Вылечено: `git config core.autocrlf true`
  (репо-локально, `.git/config`, общий для Windows- и WSL-git) + перевыкладка `.sh` через
  `git checkout` → LF. Гейт зелёный.
- **Проба БД через `psql` с пайпом из PowerShell:** первый прогон упал на BOM (`﻿`) в начале
  SQL. Обход: `$OutputEncoding = New-Object System.Text.ASCIIEncoding` перед пайпом.
- **Локальные тесты: 11 из 544 упали по таймауту хука `createTestDb()`** (PGlite, дефолт 10 с
  не хватает на этой Windows-машине), перезапуск тех же файлов с `--hookTimeout=120000` —
  зелёные (36/36). Это медлительность среды, а не регрессия: на CI 19.10 тот же код был
  зелёным. Локально гонять `npx vitest run <файл> --hookTimeout=120000`.
- **Локальный `npm install` на этой машине идёт 9+ минут и рвётся на ECONNRESET** (прокси
  127.0.0.1:10809 нестабилен) и на EPERM-очистке в `node_modules`. `node_modules` после pull'а
  23.10 был сильно устаревшим (`next` 16.2.7 против `package.json` ^16.3.8) — поэтому локальный
  typecheck падал на «Cannot find module», пока зависимости не переустановили.
