## Прод-инфра (для следующей сессии)

- **ssh:** алиасы `karman` и `GONBA`. Первый коннект в сессии может отвалиться по таймауту
  (03.09 так и было) — повторить, прежде чем считать бокс недоступным. Деструктив по прод-БД —
  только с подтверждением владельца в том же ходе (#025).
- **Свежая машина требует `npm ci`** — без него `npm run deadcode` врёт «knip не найден».
- **psql по ssh:** `$DATABASE_URL` в env юзера нет, путь к env-файлу — из юнита
  (`systemctl show karman -p EnvironmentFiles --value`). Рабочая форма:
  `ssh karman 'set -a; . <env-файл>; psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f -'`, SQL — через
  stdin, `\pset pager off` первой строкой. Колонки аудита: `at`, `action`, `detail`, `actor`;
  акторы — `owner:1`, `passport:<label>`, `token:skm_…`, **`room:<slug>`** (grant по токену).
- **Логи Actions публичны, `vars` в них не маскируются.** Recon-чувствительное — только в
  `secrets`. Новый шаг с дампом проверять по НАСТОЯЩЕМУ выводу с пустым грепом.
- **Внешние URL проверять С БОКСА** — с рабочей машины исходящий HTTPS идёт через прокси.
- **`main` защищён:** required check `gates`, PR обязателен, `enforce_admins`. Мерж после
  зелёного CI: `gh pr merge <N> --squash --delete-branch` (без `--admin`).
- **Миграции:** `deploy-prod.yml` блокирует авто-деплой на коммите с новой миграцией →
  применить psql'ом, затем `gh workflow run deploy-prod.yml --ref main`.
- **Деплой возит `scripts/`** на бокс. systemd-юниты — шаблоны, рендер `scripts/render_unit.sh`.
- **Бэкап vault:** cron 03:30, `scripts/backup_vault.sh`; список таблиц догоняет схему вручную.
