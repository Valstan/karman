## Failed approaches (этой нитки)

- **`createRemoteJWKSet` из jose как кеш ключей** — кеш живёт в памяти процесса, не
  переживает рестарт и падает вместе с недоступным issuer'ом. Нужен снимок в БД
  (`passport_jwks_cache`).
- **Сессия как новый вид предъявителя** — отвергнута в пользу «обычный токен комнаты со
  сроком»: клиент волны 1 меняется в одной строке, весь контур `/api/secrets` работает без
  правок, каскад отзыва достаётся даром.
- **Выключить `PROVISION_KEY_ENABLED` по умолчанию (как в §7 ADR)** — не стали: паспорт ещё
  не прошёл пилот, гашение живого канала до пилота — поломка под видом ужесточения.
- **`revokeIdentity`/`countLiveSessions` — написаны и удалены до коммита**: вызывающих не
  было бы до GUI-вехи, а это ровно тот born-unused класс, что рецидивировал трижды.
- **Тревога «приложение пишет сканы в релиз-каталог» — ложная.** Смотрел `MEDIA_ROOT` в
  env-файле, а он задан в systemd-юните. Проверять надо окружение живого процесса
  (`/proc/<pid>/environ`), а не тот источник, который первым попался.

## Прод-инфра (для следующей сессии)

- **ssh на Бокс 1 есть:** алиасы `karman` и `GONBA` (ключ `id_ed25519_gonba_deploy`).
  Деструктив на прод-БД — только с подтверждением владельца в том же ходе (#025).
  Соединение иногда рвётся по таймауту — повтор той же команды проходит.
- **Грабля psql по ssh:** `$DATABASE_URL` в env юзера НЕТ — переменные в
  `/etc/karman/karman.env`. Рабочая форма:
  `ssh karman 'set -a; . /etc/karman/karman.env; psql "$DATABASE_URL" -c "…"'`.
  Строки с `$` и кавычки раскрывает удалённый шелл — SQL слать целиком через stdin
  (`psql -v ON_ERROR_STOP=1 -f -`); так шли обе миграции сессии.
  Колонки аудита: `at`, `action`, `detail`, `actor` (не `created_at`/`details`).
- **Секрет через ssh/gh — не через argv** (`curl --config -`, `gh secret set` через stdin).
  Времянку (`skb_…`) генерировать локально и слать на бокс только ХЭШ — сам код на боксе
  не нужен вообще.
- **systemd-юнит деплой НЕ синхронизирует** — только `systemctl restart`. Правка юнита —
  руками: `git show HEAD:scripts/karman.service | ssh karman 'sudo tee …'` + `daemon-reload`
  + `restart`. `MEDIA_ROOT` и `KEEP_ALIVE_TIMEOUT` живут именно в юните, не в env-файле.
- **Внешние URL проверять С БОКСА, а не с PC40** — с рабочей машины исходящий HTTPS идёт
  через прокси и таймаутит. `gh` при этом с PC40 работает нормально.
- **`main` защищён технически:** required check `gates`, PR обязателен, `enforce_admins: true`.
  Мержить после зелёного CI: `gh pr merge <N> --squash --delete-branch` (без `--admin`).
- **Миграции:** `deploy-prod.yml` блокирует авто-деплой на коммите с новой миграцией →
  применить psql'ом с машины, затем `gh workflow run deploy-prod.yml --ref main`.
- **Vault:** штатный вход — паспорт CI (`docs/passport-server.md`); времянка — для рантайма
  и уже наполненных комнат (`POST /api/secrets/claim`); `VAULT_PROVISION_KEY` — break-glass,
  гасится `PROVISION_KEY_ENABLED=false`. Grant между комнатами — GUI владельца под 2FA.
  Бэкап vault: cron 03:30, `scripts/backup_vault.sh` (список таблиц догоняет схему вручную).
