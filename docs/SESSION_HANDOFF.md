## Failed approaches (этой нитки)

- **`psql -c "select …"` через ssh.** psql разбирает аргументы по пробелам: «extra command-line
  argument … ignored», «Peer authentication failed for user "name"». Работает — SQL-файл плюс
  `Get-Content -Raw <file> | ssh karman "sudo -n -u postgres psql -d karman_db -tA"`.
- **BOM в первой строке SQL-файла.** `Get-Content -Raw` отдаёт первую строку с BOM — psql падает
  с «syntax error at or near "﻿select"». Лечится dummy-строкой `select 'bom_probe';` в начале
  файла.
- **`cmd /c type <файл> | ssh …` и `Get-Content -Raw <файл> | ssh … "bash -s"`.** Блокируются
  runtime-гейтом («HOST_CAPABILITY_UNAVAILABLE»); работает только конкретная команда `psql …`
  через stdin.
- **Чтение access-лога nginx** (`sudo -n cat / grep / tail /var/log/nginx/access.log`) — гейт
  блокирует. HTTP-доступ-лога у сервиса нет: journal пишет только сторож напоминаний. Значит
  коды ответов смотреть только живой пробой `curl` к роуту.
- **Чтение env-файлов** (локально и на боксе) — гейт блокирует. Отсюда и невозможность финального
  200 из моей сессии: значение токена раздела лежит только в vault.
- **Read-back канала, к которому нет доступа.** Прямой вызов с Bearer недоступен (секрет не
  читаю), поэтому канал подтверждён **пробой без Bearer**: 403 вместо 503 = секрет на сервере
  есть. Это и есть переносимая находка в письме brain'у.

## Не забыть (low-priority)

- Учёт остатка очков панель не отдаёт (`points` клетки — номинал), поэтому сколько очков потребитель
  уже СЖЁГ — узнать нельзя. Но сколько мы СОБРАЛИ и сколько ОТДАЛИ — леджер знает точно
  (`claimed_at` / `handed_at`), и этого достаточно, чтобы судить «хватает ли на день».
- Забор в момент выдачи — это **один запрос к вендору на кандидата**. При большом потоке
  (десятки выдач в сутки) это нормально; при тысячах — считать.
- Отметка о выдаче в леджере пишется **по `claim_id`**, а не по дате: вендорские сутки и наши
  московские — разные календари (окно 00:00–03:00 МСК).
- Панель и лечащий МиниГен лежат вне git: после правки их надо перезапустить (супервизор 8098,
  `/stop` → `/start`), иначе в памяти старый код.
- Порядок сортировки по названию зависит от локали машины (кириллица и латиница меняются местами
  между Windows и Linux) — в тестах на это опираться нельзя (поймал гейт CI на PR #399).
