# AGENTS.md — единые правила для AI-агентов KARMAN

Этот файл — **единственный канонический вход для любой нейросети**: Claude Code, Codex,
Gemini CLI и будущих агентов (ADR-0011 мозга). Инструкции конкретного инструмента
(`CLAUDE.md`, `GEMINI.md`) — тонкие адаптеры: они ссылаются сюда и не дублируют правила.
Копия расходится с оригиналом молча, поэтому канон живёт в одном месте.

## Состояние проекта

- Продукт: учёт кредитов. Единое приложение Next.js 16 + TypeScript + Drizzle + Postgres.
- Прод живой: Бокс 1 (`831d0ce99bdf.vps.myjino.ru`, PG16, приложение на :3002).
- Нитка последней сессии — `docs/SESSION_HANDOFF.md`; отложенное — `docs/PENDING_FOLLOWUPS.md`;
  архитектура и операции — `docs/`.
- Почта мозгу — `mailbox/to-brain/*.md` этого репозитория; входящие —
  `../brain_matrica/mailboxes/KARMAN/from-brain/*.md` (только чтение).

## Гейты качества (предпосылка автономии)

- `npm run typecheck` — `tsc --noEmit`
- `npm run lint` — `eslint . --max-warnings 0` (flat config `eslint.config.mjs`,
  eslint-config-next 16 на ESLint 9; warnings = провал гейта).
- `npm run test` — `vitest run`
- `npm run build` — `next build`
- CI (`.github/workflows/ci.yml`) гоняет те же гейты на PR — job `gates`.

## Автономия под гейтами (#027)

Внутри PR-flow (не прямой push в main): ветка → правки → локальные гейты →
push ветки → PR → CI зелёный → авто-мерж → деплой запускается **сам** (workflow
`deploy-prod.yml` на push в main: сборка standalone-артефакта в Actions → SSH-доставка →
restart → smoke). Дождаться зелёного run'а (`gh run watch`); ручной перезапуск —
`bash scripts/deploy_remote.sh`. On-box `next build` запрещён (мандат brain 2026-06-11).

`main` защищён **технически** (с 2026-08-03): required check `gates`, PR обязателен,
`enforce_admins: true`, force-push и удаление ветки запрещены. Прямой push отклоняется
сервером даже у владельца — это не соглашение, а запрет.

## Git и совместная работа нескольких агентов

- Один агент — одна задача — своя ветка. Параллельные **пишущие** агенты — только в
  отдельных `git worktree`; двух пишущих в одном рабочем дереве не запускать.
- Перед правкой — `git status`. Незнакомые изменения в дереве считай чужими: не удалять,
  не форматировать попутно, не включать в свой коммит, не прятать в `stash`.
- Не переключай ветку в дереве, которым может пользоваться другой агент.
- Границы задачи (какие файлы трогаешь) объявляй в описании PR. Пересеклись — второй
  ждёт мержа первого и обновляет свою ветку.
- Один PR — одна задача. Коммиты — Conventional Commits.
- После обрыва связи состояние восстанавливается из Git/PR, а не по памяти чата
  (исполняемая памятка — `.claude/commands/obriv.md`).

Межмодельная память — **только Git**: коммиты, PR, `docs/SESSION_HANDOFF.md`, `mailbox/`.
Чат одной модели не является источником истины для другой.

## Соседи по экосистеме (ADR-0007 мозга)

Sibling-репо (`../<project>/`) можно читать **read-only напрямую** (перед чтением —
`git pull --ff-only`), без письма мозгу. Писать/коммитить в чужой репо нельзя; «пусть сосед
сделает X» — только через мозг. Если построил ЗАВИСИМОСТЬ от чужого API/формата — письмо мозгу.

## Черта, которую НЕ пересекаем без подтверждения (#025)

Необратимые операции с прод-данными подтверждаются владельцем **в том же ходе**,
где будет выполнена команда: `DROP`/`DELETE`/`UPDATE`/`TRUNCATE` на живой прод-БД,
прод-миграции на живых данных, `rm` прод-путей (`media/`, бэкапы), `systemctl stop`.
Это касается и команд, завёрнутых в `ssh karman "..."` — деструктив внутри кавычек
permissions-префиксом не ловится, поэтому правило семантическое: увидел такую
команду — сначала спроси владельца. Read-only probe по ssh — можно без вопросов.

## Исполняемые памятки

Лежат в `.claude/commands/` — несмотря на имя каталога, их workflow применим любому агенту:

- `start.md` — открыть сессию (sync → handoff → почта brain → ре-триаж отложенного);
- `close_session.md` — закрыть сессию (всё в Git через PR, обновить handoff, sync-гейт);
- `obriv.md` — восстановление после обрыва связи.

## Какие AI-файлы хранить в Git

Коммитить: `AGENTS.md` (канон), `CLAUDE.md` и `GEMINI.md` (адаптеры),
`.claude/commands/`, `.claude/settings.json`, `.claude/launch.json`,
`docs/`, `mailbox/`.

Не коммитить: `.claude/settings.local.json` (машинно-локальные разрешения),
кэши и сессии `.codex/`, `.gemini/`, `.agents/`, `.env*`, ключи, токены, логи,
`media/`, `backups/`.

Секреты не должны жить в репозитории даже под защитой `.gitignore`.
